# 架构设计

## 概述

KnowledgeGraph 采用五层架构设计，每层从上一层派生，可独立重建。

## 五层架构详解

```
┌──────────────────────────────────────┐
│  L5  平台交互层                      │
│  ─────────────────────────────────   │
│  目标: 乐享/IMA/WPS 知识库           │
│  数据: 同步后的百科页面和原始文件     │
│  操作: 只读查询、展示、笔记同步       │
│  重建: 从 L4 完全重建                │
├──────────────────────────────────────┤
│  L4  Wiki 百科层                     │
│  ─────────────────────────────────   │
│  目标: 结构化百科页面                │
│  数据: entities/*/, mappings/*/,     │
│        index.md, log.md               │
│  操作: 交叉引用、矛盾标记、索引更新  │
│  重建: 从 L2 + L3 完全重建          │
├──────────────────────────────────────┤
│  L3  知识图谱层                      │
│  ─────────────────────────────────   │
│  目标: 实体-关系图谱                 │
│  数据: entities.json, graph.json    │
│  操作: 抽取、聚类、查询、可视化      │
│  重建: 从 L2 完全重建               │
├──────────────────────────────────────┤
│  L2  统一文档层                      │
│  ─────────────────────────────────   │
│  目标: 统一 Markdown 格式            │
│  数据: converted/<sha>/*.md          │
│  操作: 格式化、分块、索引           │
│  重建: 从 L1 完全重建               │
├──────────────────────────────────────┤
│  L1  原始文档层                      │
│  ─────────────────────────────────   │
│  目标: 原始文件（只读，不可变）      │
│  数据: sources/<category>/*          │
│  操作: 哈希锁定、追加               │
│  重建: N/A（不可修改）              │
└──────────────────────────────────────┘
```

## 层间依赖关系

| 层级 | 数据来源 | 可从谁重建 | 关键工具 |
|------|----------|-----------|----------|
| L1 | 用户导入 | 不可重建 | SHA-256 |
| L2 | L1 | L1 | MarkItDown |
| L3 | L2 | L2 | Graphify + AI |
| L4 | L2 + L3 | L2 + L3 | Agent (模板) |
| L5 | L4 | L4 | MCP 工具 |

## 数据流向

```
用户文档
    │
    ▼
[ingest] ─── L1: sources/ ─── manifest.jsonl (SHA-256)
    │
    ▼
[markitdown] ─── L2: converted/<sha>/*.md
    │
    ▼
[extract-entities] ─── L3: graphify-out/entities.json
    │                   └── graphify-out/graph.json (可选)
    │
    ▼
[build-wiki] ─── L4: wiki/entities/*/, wiki/mappings/*/
    │
    ▼
[sync] ─── L5: 乐享/IMA/WPS 知识库
```

## domain_config.yaml 在架构中的角色

`domain_config.yaml` 是本 Skill 与 KnowPilot 的核心区别。它定义了：

1. **实体类型 Schema** — 决定 L3 图谱中的节点类型
2. **关系类型** — 决定 L3 图谱中的边类型
3. **属性定义** — 决定每个实体类型的字段
4. **文档分类** — 决定 L1 的目录结构
5. **映射配置** — 决定 L4 的映射页面
6. **同步配置** — 决定 L5 的目标平台

通过修改 `domain_config.yaml`，同一个 Skill 可以适配任意领域。

## 与 KnowPilot 的对比

| 维度 | KnowPilot | KnowledgeGraph |
|------|-----------|----------------|
| 领域 | 固定（分析化学） | 可配置（任意领域） |
| 实体类型 | 硬编码 4 种 | YAML 配置 N 种 |
| 关系类型 | 硬编码 | YAML 配置 |
| 抽取方式 | 正则表达式 | AI 辅助（基于配置） |
| 页面模板 | 固定 3 种 | 通用默认 + 可选自定义 |
| 同步目标 | 仅 IMA | 乐享/IMA/WPS/本地 |
| 可扩展性 | 需改代码 | 改 YAML 即可 |
